# 明道中医问诊台 · 界面优化设计 v1（提案，未改产品代码）

- 状态：**设计提案**。只写"应该长成什么样、为什么、怎么验收"，不改代码。
- 视角：软件界面设计 + **中医师一天的真实动线**（不是把 SaaS 后台做得更精致）。
- 参照：上游 `docs/DESIGN-UI-v1.md` 的**方法**（结论先行 / 痛点带证据 / 每条带验收 / 按"一天被绊几次"排序），
  但**结论不同** —— 上游是通用 Agent 对话台，本层是**中医问诊台**，优先级的排序依据不一样。
- 约束：Electron + 浏览器原生 ES 模块、零构建、零运行依赖；不改内核事件协议。

---

## 0. 结论先说

1. **最大的问题不是"不好看"，而是"它像一个表单，不像一张诊台"。**
   医师坐下 30 秒内要做的是：认人 → 望舌切脉 → 口述记录 → 出结论。
   现在这四步被摊在一张长表单 + 一个聊天框里，**眼睛要在两个区域来回跳**。
2. **复诊是中医的常态，但界面把初诊当默认。** 复诊真正需要的是"**这次和上次比**"，
   而现在要先离开诊台、去患者页翻历史、再回来填表 —— 这是每天重复十几次的摩擦。
3. **舌象与脉象是中医最有诊断价值的两个输入，却排在表单中段。**
   舌象现在解决了"能拍"，还没解决"**拍完能顺手看一眼**"；脉象仍是自由文本框，
   而脉象是**有限词汇**（浮沉迟数虚实滑涩…），敲字远不如点选。
4. **字太小。** 现在的正文 12.5–13.5px、提示 11.5px。中医师群体年龄偏大，
   这不是审美问题，是**能不能看清**的问题。
5. **界面的"颜色语言"没有语义。** 玉青同时用于：按钮、链接、数字、强调、选中态。
   医师无法用颜色快速判断"哪个是主操作"，最后只能靠读字。

## 1. 中医师的一天（优先级排序的依据）

| 时刻 | 医师在做什么 | 界面对应的动作 | 目前被绊在哪 |
| --- | --- | --- | --- |
| 坐下 | 叫下一位患者 | 新患者 / 找回老患者 | 患者检索在另一个页面 |
| 前 30 秒 | **望舌、切脉** | 拍照、记脉象 | 舌象在表单中段；脉象要打字 |
| 1–3 分钟 | 口述主诉/现病史 | 填表 | 长表单，**发送键在底部，要滚动** |
| 3–5 分钟 | 看结论、追问 | 读正文、补问 | 正文与表单左右分栏，视线跳 |
| 收尾 | 落盘、约复诊 | 发送、随访 | 已解决（一键直接问诊） |
| **复诊** | **和上次比** | 翻历史、逐项对照 | 要离开诊台去患者页 |

> 排序依据：**一天被绊几次 × 每次损失多少注意力**。
> 复诊对比（每天十几次）＞ 舌象/脉象录入（每天每位一次，但直接影响判断）＞ 字号（每次看都影响）＞ 视觉一致性。

## 2. 设计原则（5 条，每条一句话 + 为什么对中医问诊台重要）

1. **一张诊台，不要两个页面。** 认人、望舌、记录、看结论必须在同一屏 —— 医师的眼睛不该在左右两栏之间往返。
2. **望舌切脉优先。** 舌象与脉象是唯一"看一眼就有信息量"的输入，应该在最上面、最大、最省事。
3. **复诊是默认场景，不是例外。** 打开诊台先问"是不是老患者"，是就直接把上次的记录摆在旁边。
4. **能用点选就不用打字。** 脉象、舌质、舌苔、寒热虚实都是**有限词汇**；打字慢、易错、还得分心。
5. **字号与对比度优先于精致。** 11px 的辅助文字在医师的显示器上等于没有。宁可少放两个字段。

## 3. 改造清单（现状 → 改成什么 → 为什么 → 验收）

### 3.1 ★★★ 诊台一体化：患者条常驻在顶部

**现状**：患者身份靠"当前会话"隐式承担；要确认是不是同一个人得去患者页。
**改成**：诊台顶部一条**患者条**：`姓名 · 性别 · 年龄 · 第 N 次就诊 · 上次就诊 3 天前`，
右侧三个按钮：`换人` / `复诊对比` / `新建患者`。
**为什么**：中医最怕**认错人、串病历**（本层已有 B-005 串会话风险）。
**验收**：任何时刻只看顶部一行就能回答"我在看谁、第几次"；换人不需要离开诊台。

### 3.2 ★★★ 复诊对比常驻：把"上次"摆在每个字段旁边

**现状**：要对比历史，得离开诊台 → 患者页 → 逐次展开。
**改成**：选中老患者后，表单每个字段右侧出现一列浅色小字「上次：咳嗽 2 月，干咳少痰」；
底部一条「本版比上次：3 项变化」+ 可展开的四态对比（消失/减轻/无变化/加重）。
**为什么**：这是中医复诊的**核心判断动作**，每天重复十几次。
**验收**：复诊时不离开诊台即可完成"逐项对照"；对照内容只读、不参与提交。

### 3.3 ★★ 舌象与脉象前置 + 脉象点选

**现状**：舌象在表单中段（已能拍照/拉近）；脉象是自由文本框。
**改成**：
- 舌象区移到**表单最上**，拍完在诊台内直接显示大图（可点开看原图），旁边一个 `重拍`。
- 脉象改为**点选 chip**：`浮 沉 迟 数 虚 实 滑 涩 弦 细 濡 紧` + 一个"补充说明"文本框。
**为什么**：这是"看一眼就有信息量"的输入，位置与录入方式都应该最省事。
**验收**：新患者从坐下到拍完舌象 + 记完脉象 ≤ 3 次点击 + 无需打字。

### 3.4 ★★ 底部常驻操作条（不再滚动去找发送）

**现状**：`直接问诊（合成并发送）` 在长表单底部，填到一半要滚动才能点。
**改成**：诊台底部**吸底条**：左 `已填 6/10 项`，右 `合成到输入框` / **`直接问诊`**（主按钮）。
**为什么**：填表时手指与视线都在中段，主操作不该在屏幕外。
**验收**：任何滚动位置都能一眼看到主按钮；缺必填项时它**变灰**并就地提示缺哪两项。

### 3.5 ★★ 字号与密度：给医师的显示器让路

**现状**：正文 12.5–13.5px、提示 11.5px。
**改成**：正文 **15px**、辅助 **13px**、行高 1.65；设置里给一档 **字号：标准 / 大**（整站 `rem` 缩放）。
**为什么**：中医师年龄偏大，11px 在 1080p 上等于不可读。
**验收**：`字号：大` 下所有正文 ≥ 16px 且布局不溢出；设置里可即时预览。

### 3.6 ★ 颜色语义化（只改用法，不改配色）

**现状**：玉青同时承担按钮/链接/数字/强调/选中。
**改成**：**玉青 = 主操作与选中**；**青色 = 信息与链接**；**琥珀 = 需要注意（缺项、过期）**；**红 = 阻断（错误、红线命中）**。
**为什么**：医师需要用颜色**扫**出"下一步该点哪"，而不是读字。
**验收**：任一屏上"主操作"唯一且为玉青；同屏不出现两种同权重的强调色。

### 3.7 ★ 空态与引导（新用户第一次打开）

**现状**：打开就是一张空表单 + 空对话，没有"从哪开始"。
**改成**：空态三步卡：`① 填密钥（仅首次）` → `② 填患者与主诉` → `③ 点直接问诊`，
每步一句为什么；完成后卡片消失，不再出现。
**验收**：新装用户不看文档能独立完成第一次问诊。

### 3.8 ☆ 键盘优先（医师更快的路径）

`⌘/Ctrl+Enter` 直接问诊；`⌘/Ctrl+K` 换患者；`⌘/Ctrl+Shift+T` 拍照；
Tab 顺序 = 望→闻→问→切（与填表顺序一致）。
**验收**：不摸鼠标可完成一次完整问诊。

## 4. 视觉稿（用现有组件重排，不引入新框架）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 患者条：王五 · 女 · 41岁 · 第 2 次就诊 · 上次 3 天前   [换人][对比][新建] │
├───────────────────────────────────┬──────────────────────────────────┤
│ 舌象（大图 / 拍照 / 拉近 / 重拍）   │  工具执行区（患者识别·落盘·对比）  │
│ 脉象 chip：浮 沉 迟 数 虚 实 滑 涩  │  ─────────────────────────────── │
│ 主诉 / 现病史（两栏，右侧浅色"上次"）│  问诊正文（唯一滚动区）           │
│ 闻/问：寒热 汗 饮食 二便 睡眠       │                                  │
│ 切：脉象补充说明                     │                                  │
├───────────────────────────────────┴──────────────────────────────────┤
│ 已填 6/10 项                              [合成到输入框]  [ 直接问诊 ] │
└──────────────────────────────────────────────────────────────────────┘
```

**信息分层**：患者条 / 舌象 / 主按钮**常驻**；舌质舌苔、二便睡眠等**按需展开**；
复诊对比**常驻但只读**。

## 5. 优先级与工作量（我建议的实施顺序）

| # | 改动 | 价值 | 工作量 | 风险 |
| --- | --- | --- | --- | --- |
| 3.4 | 底部吸底操作条 | 每天几十次 | 小（纯 CSS + 一段 JS） | 极低 |
| 3.5 | 字号 + 字号档位 | 每次看都影响 | 小（改 CSS 变量 + 一档设置） | 低 |
| 3.1 | 患者条常驻 | 防串病历 | 中（复用患者册数据） | 低 |
| 3.3 | 舌象前置 + 脉象 chip | 影响判断质量 | 中 | 低 |
| 3.2 | 复诊对比常驻 | 每天十几次 | **大**（需要每字段的上次值 + 对比视图） | 中 |
| 3.8 | 键盘优先 | 熟手提速 | 中 | 低 |
| 3.6/3.7 | 颜色语义 / 空态 | 观感与上手 | 小～中 | 极低 |

**我建议先做 3.4 + 3.5 + 3.1**（三件都小、都立刻可感、都不碰数据链路），
**再单独一版做 3.2**（复诊对比是价值最大的，但要动数据组织，值得单独排期）。

## 6. 我**不**建议做的事（避免走偏）

1. **不要引入 UI 框架/构建链** —— 与"零依赖、可审计、离线可用"的约束冲突。
2. **不要让界面暗示"AI 下了诊断"** —— 本层的红线是"不输出诊疗结论、判断权归医师"；
   界面上的动词要用「整理 / 归纳 / 提示」，不用「诊断 / 判定 / 建议服用」。
3. **不要为了好看压缩字号** —— 医师看不清，再美也没用。
4. **不要把统计/版本动态这类站点的东西放进诊台** —— 那是官网的职责。

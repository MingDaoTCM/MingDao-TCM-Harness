# 得一中医层 · 架构与设计

> 本文描述**当前实现**：垂域 Pack（Pack API v1）+ 路线 A 的 Dify Provider + 独立问诊台。
> 上游版本对齐见根 [`README.md`](../README.md) 的「与上游的版本关系」。
>
> ⚠ 本文 2026-09-16 重写过一次：此前它描述的还是 **Pack 迁移之前**的系统
> （旧运行链路、3 个工具、十问字段），与代码全面脱节——读它会得到一套不存在的架构。

## 一、上下游关系

```
Line A  MingDao-Harness      通用内核（开源）
          ↑ 依赖（扩展点）
Line B  Deyi-TCM-Harness     中医垂域层（本仓库，私有）
```

本层**只通过 Line A 的扩展点接入，绝不修改内核源码**：

| 扩展点 | 安装位置 | 本层用它做什么 |
|---|---|---|
| 垂域 Pack | `$MINGDAO_HOME/packs/tcm/` | 5 个域工具 + 4 条红线约束 + 1 段领域提示词（**域能力的主体**） |
| 自定义 Provider | `$MINGDAO_HOME/providers/dify.mjs` | Dify 主问诊 + 每轮的工具编排判定（**路线 A**） |
| 独立问诊台 | `tools/tcm-ui/` | 自建前端 + 零依赖薄代理，消费内核文档化的 SSE 契约 |

- **内核 bug 在上游 Line A 修**，本层不重复造；两条线各自独立仓库、独立发布节奏。

## 二、运行链路（路线 A）

```
医师一句话
   │
   ├─(1) Provider 先问一次小模型（编排器，默认 deepseek-v4-flash，可切本地）
   │      「这一轮要不要调工具？」——只把 pack__* 工具交给它，通用工具不交
   │        ├─ 要 → 返回 toolCalls 交回内核，由内核走「权限 → 审计 → 费用归因 → 约束校验」执行
   │        └─ 不要、或判定失败 → 走 (2)
   │
   ├─(2) Dify 流式问诊：产出临床正文（逐字），成为 provider 的 res.text
   │      · query 里注入「本次第几诊 + 上次病历」——由 Pack 的 patient_lookup 权威产出
   │      · 该正文**受内核输出红线约束**（agent.js 的 applyOutputConstraints）
   │
   └─(3) 工具侧（内核执行）
         患者定位 → 登记 → 病历落盘 → 四态对比 → 回访看板
```

> **为什么是路线 A**：只有 A 能让 Dify 的临床正文**逐字呈现**，且**同时受输出红线约束**
> —— 工具吐出的文本（含 `io.writeText`）不在红线覆盖范围内。
> 代价是每回合多一次小模型调用（约 +1~2 秒）。
>
> **编排判定失败一律回落为纯问诊**：宁可少调一个工具，也不能让医师问不了诊。

## 三、患者标识模型（医疗级）

### 为什么不是「姓名」

同名在现实中极常见，用姓名做唯一键会**混病历**（医疗事故级风险）。

### 主键：病历号

- 注册表 `patients.json`：

  ```json
  { "nextId": 3,
    "patients": {
      "P001": { "name":"张三","birth":"1985","sex":"女","createdAt":"…","lastVisitAt":"…","visits":2 }
    } }
  ```

- 首诊分配 `P001`、`P002`…（`nextId` 自增，稳定唯一）；
- 快照按患者隔离：`$MINGDAO_HOME/intake/<病历号>/case-<时间戳>.json`。

### 匹配顺序

1. **病历号**（`P001`）→ 精确命中；
2. **姓名 + 出生年 + 性别** → 收窄到唯一；
3. **多个同名且无法收窄** → **拒绝落盘、拒绝问诊**，返回候选列表请医师确认：

```
⚠ 系统中有 2 位患者叫「张三」，为避免混病历，请确认是哪位：
· 张三（1985年生，病历号 P001，末次就诊 2026-09-01）
· 张三（1990年生，病历号 P002，末次就诊 2026-08-15）
```

### 就诊次数由本层注入

Dify 用 `sys.dialogue_count`（会话轮次）猜「第几诊」会错位（会话 id 跨就诊未重置）。
**本层按「该患者历史快照数 + 1」明确注入**：

```
【就诊次数】本次为该患者第 3 次就诊（三诊）；上次为第 2 次就诊，病历如下，
请回顾并对比辨证，不要当作新病案、不要自行重算次数。
<上次病历块>
```

## 四、五个 Pack 工具

工具注册名由内核自动加前缀，形如 `pack__tcm__<name>`。

| 工具 | 读/写 | 职责 | 关键红线 |
|---|---|---|---|
| `patient_lookup` | 只读 | 按病历号 / 姓名+出生年+性别 定位；**同名多命中返回候选、绝不静默挑一个**；并交出渲染好的「上次病历」块 | — |
| `patient_register` | 写 | 登记新患者并分配病历号；同名已存在则**拒绝登记** | — |
| `intake_collect` | 写 | 结构化落盘；**必填齐全才写**（缺项回报「请继续采集」） | 缺项绝不编造 |
| `visit_compare` | 只读 | 复诊四态对比（消失 / 减轻 / 无变化 / 加重） | 只陈述事实，不判疗效 |
| `followup_board` | 只读 | 回访看板 / 单患者时间线 + 异常预警 + 随访话术草稿 | 话术标注「草稿·需医师确认」 |

四条红线（**内核强制**，不依赖模型自觉）：

| id | kind | 作用 |
|---|---|---|
| `no-cross-patient-intake` / `no-cross-patient-compare` | `tool-arg-require` | 缺 `patientId` 的落盘/对比 → PreToolUse 阻断 |
| `ten-questions-complete` | `completeness` | 主诉 / 现病史缺任一项 → PostToolUse 拒绝该结果 |
| `no-efficacy-conclusion` | `output-forbid` | 结论性疗效表述 → `warn`（提示 + 审计，**不替换正文**） |

> `output-forbid` 作用在 agent 正文上，**与 provider 无关** —— 所以「不输出诊疗结论」
> 这条红线**装上 Pack 即生效**，不必等接线。

> **随访口径也只此一处**：`followupStatus(patient)` —— 超期（≥ `OVERDUE_DAYS` 14 天）/
> 临期（距超期不足 `DUE_SOON_DAYS` 3 天）/ 正常 / 未就诊。
> 回访看板与问诊台的提醒条都必须走它：两处各写一遍天数比较，改阈值或差一天就会对不上 ——
> 医师会在两个界面看到**不同的「超期人数」**，而且都不报错。

  现改为**门诊病历结构**；舌象/脉象此前无处可放，现在单独留字段；
- 「重大疾病诊断原样保留、绝不概括」这条硬规则由 `xianbingshi` 承担（原 `zhenduan` 字段并入）；
- 字段全集与中文标签的唯一定义处：`layer/packs/tcm/pack.mjs` 的 `ALL_FIELDS` + `FIELD_CN`。

## 六、两条不可退让的契约（踩过坑才定下的）

1. **患者数据只有一个写入者 —— Pack。**
   Provider **不写** `patients.json` / `intake/**` 的任何字节。
2. **字段语义只有一个定义处 —— Pack 的 `FIELD_CN` + `ALL_FIELDS`。**
   Provider 只转发 `renderVisitBlock()` 的成品，**零字段知识**。

> 第 2 条是 2026-09-16 补上的，起因是一次**静默失真**：provider 曾自己维护一份旧字段表，
> 病历结构重构后没跟上 → 复诊注入的「上次病历」除主诉外全部渲染成「未提及」，
> 现病史与四诊整段丢失，**不报错、不崩溃、测试还是绿的**（测试夹具也用旧字段）。
>
> 规矩：**同一份契约定义在两处，迟早会漂移**。回归防线见 `pack.test.mjs` 的字段契约断言
> （`FIELD_CN` ↔ `ALL_FIELDS` 一一对应、渲染块不含旧字段名）。

## 七、已知取舍与后续

1. **「四诊」歧义**：中医「四诊」= 望闻问切。就诊次数统一说「第 N 诊 / 第 N 次就诊」，避免混淆。
2. **舌象照片**依赖 Dify 应用侧也开视觉；照片传不上去不挡住问诊（正文照常，只是这次没有图片）。

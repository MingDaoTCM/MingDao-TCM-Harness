# 得一中医层 · 架构与设计

## 一、上下游关系

```
Line A  MingDao-Harness      通用内核（开源）
          ↑ 依赖（扩展点）
Line B  Deyi-TCM-Harness     中医垂域层（本仓库，私有）
```

- **本层只通过 Line A 的扩展点接入**：自定义 Provider（`<MINGDAO_HOME>/providers/*.mjs`）、预设、`config.tools`；
- **内核 bug 在上游 Line A 修**，本层不重复造；
- 两条线各自独立仓库、独立发布节奏。

## 二、运行链路

```
患者/医师一句话
   │
   ├─(1) 患者识别（DeepSeek 关思考）
   │     提取 病历号/姓名/出生年/性别 → 查注册表 patients.json
   │       ├─ 命中唯一 → 复诊，读该患者上次快照
   │       ├─ 多个同名 → 返回候选，请医师确认（不落盘、不问诊）
   │       └─ 无命中 → 首诊，分配新病历号
   │
   ├─(2) 注入就诊次数 + 上次病历（复诊时）→ 调 Dify（流式）
   │     Dify 产出的就是「问诊结果」（追问/辨证/知识），本层不重写
   │
   ├─(3) 结构化落盘（DeepSeek 关思考）
   │     只看【患者消息】提取十问 → 写入 intake/<病历号>/case-<时间戳>.json
   │     复诊时以上次快照为基底做「未变沿用、变化用新」的合并
   │
   └─(4) 复诊四态对比（DeepSeek 关思考）
         消失 / 减轻 / 无变化 / 加重 —— 只陈述事实，不作疗效结论
```

## 三、患者标识模型（医疗级）

### 为什么不是「姓名」

同名在现实中极常见，用姓名做唯一键会**混病历**（医疗事故级风险）。

### 主键：病历号

- 注册表 `patients.json`：
  ```json
  { "nextId": 3,
    "patients": {
      "P001": { "name":"张三","birth":"1985","sex":"女","createdAt":"…","lastVisitAt":"…","visits":2 }
    } }
  ```
- 首诊分配 `P001`、`P002`…（`nextId` 自增，稳定唯一）；
- 快照按患者隔离：`intake/<病历号>/case-<时间戳>.json`。

### 匹配顺序

1. **病历号**（`P001`）→ 精确命中；
2. **姓名 + 出生年 + 性别** → 收窄到唯一；
3. **多个同名且无法收窄** → **拒绝落盘、拒绝问诊**，返回候选列表请医师确认：

```
⚠ 系统中有 2 位患者叫「张三」，为避免混病历，请确认是哪位：
· 张三（1985年生，病历号 P001，末次就诊 2026-09-01）
· 张三（1990年生，病历号 P002，末次就诊 2026-08-15）
```

### 就诊次数由本层注入

Dify 自己用 `sys.dialogue_count`（会话轮次）猜「第几诊」会错位（会话 id 跨就诊未重置 → 三诊被猜成四诊）。
**本层按「该患者历史快照数 + 1」明确注入**：

```
【就诊次数】本次为该患者第 3 次就诊（三诊）；上次为第 2 次就诊，病历如下，
请回顾并对比辨证，不要当作新病案、不要自行重算次数。
```

## 四、三个工具

| 工具 | 触发 | 产出 | 关键红线 |
|---|---|---|---|
| **工具一 问诊采集** | 直接描述病情 | 十问追问 → 结构化病历草稿 | 缺项绝不编造 |
| **工具二 复诊对比** | `复诊：<病历号>，…` | 四态变化表 | 只陈述事实，不判疗效 |
| **工具三 回访追踪** | `回访` / `回访 P003` | 看板 + 时间线趋势 + 异常预警 + 随访话术 | 话术标注「草稿·需医师确认」 |

## 五、病历快照字段

```
patientId 病历号 · patientName · birth · sex
zhushu    主诉（含疾病诊断+主要症状）
zhenduan  诊断/重大疾病（癌症/肿瘤/糖尿病/心脏病等，必须原样保留，绝不省略）
hanre 寒热 · han 汗 · toushen 头身 · erbian 二便
yinshi 饮食 · xiongfu 胸腹 · kouke 口渴 · jiubing 旧病
collectedAt 采集时间 · source 来源
```

> **诊断字段是硬要求**：早期实现漏了这个字段，导致「宫颈癌」这类重大诊断被当噪音过滤——已修复并强制原样保留。

## 六、已知取舍与后续

1. **`四诊` 歧义**：中医「四诊」= 望闻问切。就诊次数统一说「第 N 诊 / 第 N 次就诊」，避免与术语混淆。
2. **通名账号被剔除**：`providers/dify.mjs` 中患者提取失败时用时间戳兜底，避免未命名患者互相混。
3. **正式版待做**：患者列表/管理界面、多患者并发隔离的更严格校验、随访日程与提醒。
